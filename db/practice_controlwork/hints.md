# Отдельные подсказки — без готовых запросов

1. Среднее считай с тем же фильтром статуса, что и внешнюю выборку.
2. EXISTS проверяет наличие строк, а не значение выбранного столбца.
3. Свяжи внутреннюю и внешнюю выборку по складу, дай им разные алиасы.
4. Проверка отсутствия должна охватывать и позицию, и статус её заказа.
5. «Нет категории, для которой у покупателя нет покупки».
6. ROW_NUMBER; порядок внутри окна и финальный ORDER BY — разные вещи.
7. Сначала агрегация по SKU, потом ранжирование, потом фильтрация во внешнем SELECT.
8. Сначала одна строка на склад/день; затем SUM с ROWS UNBOUNDED PRECEDING.
9. LAG; вычитание timestamptz даёт interval.
10. generate_series + все склады + LEFT JOIN дневных сумм; затем окно по семи строкам уже полного календаря.
11. EXTRACT(EPOCH FROM interval) переводит интервал в секунды. У GREATEST в PostgreSQL есть особенности обработки NULL — сохрани NULL явно.
12. Нижняя граница включена, верхняя исключена; NULL верхней границы проверь отдельно.
13. Для пересечений подойдёт self join или tstzrange с границами '[)'; сначала исключи/отдельно обработай неверные интервалы. Разрывы удобно искать с LEAD.
14. Проверка повтора должна предшествовать закрытию версии. Не обновляй price_id существующей версии.
15. LEFT JOIN сохраняет позиции без совпадения. Для диагностики неоднозначности сначала посчитай совпадения на позицию.
16. DDL PostgreSQL тоже участвует в откате транзакции.
17. SAVEPOINT для обработки ошибки создаётся до ошибочного запроса.
18. Блокируй/проверяй обе строки; для общего случая используй одинаковый порядок блокировок по ключу.
19. Условие и изменение одной строки выполняй одним оператором. RETURNING показывает успех.
20. При READ COMMITTED UPDATE после ожидания проверяет условие на обновлённой версии строки. Заранее вычисленная константа и выражение qty-3 ведут себя по-разному.
21. COUNT с FILTER; деление не должно быть целочисленным; NULLIF защищает знаменатель.
22. Условный UPDATE, RETURNING INTO, FOUND; при неудаче отдельно различи отсутствующий ключ и недостаток. Квалифицируй имена столбцов во избежание конфликта с переменными.
23. FOR ... IN SELECT; LEFT JOIN и COUNT(order_id), а не COUNT(*).
24. Сначала валидация и чтение истории, затем изменения. Не смешивай идемпотентный повтор и конфликт в тот же момент времени.
25. Все три вызова должны находиться внутри одного BEGIN ... EXCEPTION ... END. Изменения блока откатываются до выполнения его обработчика; переменные PL/pgSQL могут сохранять присвоенные значения.
